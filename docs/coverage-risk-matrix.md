# Coverage risk matrix

PageLumen uses risk-based coverage rather than a single percentage threshold.
The report generated by `make coverage` is diagnostic evidence and does not
prove UI, TCC, VoiceOver, or physical-device coverage.

| Risk boundary | Automated evidence | Remaining external evidence |
| --- | --- | --- |
| Document parsing, budgets, OCR fallbacks | Processor tests, fixture corpus, performance guards | Scanned-image device latency and memory |
| Persistence and retention | Persistence and store tests | Release migration injection |
| Exports and dependencies | Snapshots, DOCX validator/unzip consumer, Stirling fakes | Word/Pages/LibreOffice rendering |
| AI and translation | Provider fakes, availability/fallback tests, evaluation contract | Eligible/ineligible Mac and model comparison |
| Platform permissions and UI | Deterministic XCUITest routes and injectable permission seams | TCC, picker, VoiceOver, participant execution |

The report is regenerated for each release-candidate verification run and is
kept separate from the manual acceptance record.
